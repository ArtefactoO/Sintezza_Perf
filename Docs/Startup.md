# Login and reload reports

Implemented for Forever in Unreleased, keeping version 0.7.0. The user's requested outcomes are a readable standalone button/highlight style and a loading report that helps investigate delays.

## Measurement

`Startup.lua` loads first in Perf's TOC and records an elapsed-clock timestamp. It observes `ADDON_LOADED`, `PLAYER_LOGIN`, `PLAYER_ENTERING_WORLD` and `LOADING_SCREEN_DISABLED`. Only initial login or UI reload flags produce a report. When the screen event is absent for five seconds after entering the world, the fallback uses the original world-entry timestamp. A dismissal received after PLAYER_LOGIN but before entering-world is retained. Once saved, the observer unregisters all events.

`/sperf reload` saves an elapsed-clock and wall-clock marker before invoking ReloadUI. The next UI instance accepts it only for a reload within 300 seconds, with a nonnegative elapsed offset and agreement with wall-clock elapsed time within two seconds. Missing, stale, reset or disagreeing clocks fall back to Perf's first timestamp. The marker is consumed. Character login always uses the first-code timestamp. Optional dependencies, including Theme, can load earlier than Perf.

New reports store the PLAYER_LOGIN split and an ordered trace of observed loading markers: Perf startup, ADDON_LOADED folder names, PLAYER_LOGIN, PLAYER_ENTERING_WORLD when it falls within the measured interval, and the terminal event. Addon notifications continue to be observed after PLAYER_LOGIN and world entry until the recorded endpoint. The trace has at most 128 markers: the first 127 observed markers, including Perf startup, followed by the terminal marker. When the limit is reached, the final link spans the omitted markers and displays their count. A world-entry fallback excludes later markers and uses the addon-event and omission counts captured at world entry.

The optional `startup.traceVersion = 1` data extends the existing history schema. Stored `trace[].at` values are relative to Perf startup; the chain helper adds a valid command-to-Perf lead and prepends `/sperf reload` when that lead is positive. The sanitizer checks ordered, bounded timestamps, valid marker kinds, addon names and explicit start/end boundaries. An invalid trace is discarded while the report's existing summary and longest intervals remain readable. Older reports retain their five longest intervals in **Details**; no chronology is inferred from that duration-ranked list. A new login or `/reload` is needed to collect a chain.

Link durations measure elapsed time from one marker to the next. Folder names identify event boundaries; they do not measure the loading time of either named addon. Multiple addons and client work can fall within each interval. The UI identifies the longer observed phase and recommends controlled repeats to test the cause. No arbitrary addon is automatically blamed or disabled.

Reports use the existing history, pin, rename, delete confirmation and text/JSON export. History retains the newest ten unpinned loading reports separately from the configured 20, 50 or 100 regular performance reports. Up to ten pinned reports are shared across both kinds, allowing at most 120 records. Background episodes therefore cannot consume the unpinned loading allowance. Migration reads the bounded 120-record set, sanitizes it and reapplies these limits; repeated migration preserves the result. Records already evicted by the previous shared limit cannot be recovered by this change. The history-setting hint states the separate loading allowance.

The sanitizer preserves older reports and rejects malformed startup records. Loading entries have their own report layout. Frame-time and CPU comparison groups apply to existing performance captures. Loading measurement adds no frame polling, memory walk or profiling-clock reads per frame. One five-second fallback callback can be scheduled after entering-world.

For example, `Mastercraft_Inbox --0.67 s--> PLAYER_LOGIN` measures the interval after the `ADDON_LOADED` notification for Mastercraft_Inbox and before PLAYER_LOGIN. It does not say that Mastercraft_Inbox took 0.67 seconds to load. An interval from Blizzard_CombatLog to Mastercraft_Inbox ends at Mastercraft_Inbox's loaded notification, so its loading code can occur within that interval. The link still does not establish which addon or client work caused the delay. Compare repeated measurements under the same conditions, changing one addon or setting at a time.

## UI

Standalone buttons use solid, full-extent surfaces for normal, hover, pressed, selected and disabled states. History rows use a subdued fill with inset actions. Theme providers remain the source of rendering when present. New strings use RU/EN through the established locale function.

`/sperf startup`, right-clicking the minimap button and **Login timing** in the main window header toggle the same cached **Login and reload timing** window. The Russian labels are **Время входа** and **Вход и перезагрузка**. Opening it from the command or minimap does not create the main window. The minimap tooltip describes both mouse actions; left-click continues to toggle the main window independently. Both mouse buttons are registered explicitly, and the right-click hook also works with Theme's minimap factory.

The loading window is 920 × 640 before appearance scaling. Its saved login/reload picker is 330 units wide. The summary shows the measured interval and phase values. New records open on **Chain**, an 880-unit panel with 832 units for compact native link units. Each unit contains the marker's full name, the time to the next marker and its outgoing arrow. Units use measured text widths, a minimum height of 24 units, six-unit gaps and the existing 12-unit name/time font. A unit wraps as a whole, keeping its arrow attached; an exceptional long name wraps inside its unit. **World visible** means LOADING_SCREEN_DISABLED was observed. The fallback ends with **World entry event**, and the scope line identifies that earlier event boundary explicitly.

The three longest positive links across the selected report receive a background highlight and textual ranks **#1–3** at their original chronological locations. Equal durations keep their observation order; zero-duration links are not ranked. Ranking spans the complete trace, including links outside the viewport, without reordering its nodes. A single pass keeps at most three ranking candidates when the selected report changes. Theme supplies panel/tint providers when available, with the standalone fallback retained. Hovering a unit shows the full name, offset from the measured start, time to the next marker, rank, omission count when applicable and interval scope.

`ns.StartupCompactTime` affects only the chain display: intervals below one second use milliseconds, including `0 ms` and `<1 ms`; a rounded 1,000 ms is shown as `1.00 s`, and longer intervals use seconds. The complete copied report retains its existing plain-text seconds format without display markup. Units are created lazily when a report opens and reused, with at most 129 units for the 128-marker trace plus an optional reload-command marker. Scrolling adds no Lua repaint callback, sampler or ticker.

Ordinary link units use a subdued flat sidebar surface, with input-color fill and soft borders at 0.22 alpha. The top three links retain their accent-dim fill, 0.6-alpha accent border and emphasized name/time at their original positions; the terminal unit stays neutral. All arrows use the same centered, muted treatment at 0.55 parent alpha. Theme supplies its shared chevron glyph with pixel snapping; the standalone fallback uses two one-pixel native lines. Fonts, layout and interaction are unchanged.

**Details** contains the explanation and complete plain-text report. History details and text exports share the same chronological text, using ASCII arrow separators such as `AddonA --0.67 s--> AddonB`. Old records open in **Details** with **Chain** disabled; their duration-ranked gaps keep separate duration, **Start** and **End** lines. Explanations use spaced paragraphs. Switching Chain/Details changes visibility and selected state while retaining the selected report, enabled report picker and chain scroll position; it does not refresh history. A new loading record refreshes an open window.

The report picker has a short titled hint. Shared Theme help sizes to its text between 140 and 260 units in width, wraps long content at that maximum and adds no blank heading when the title is empty. This change is in Theme's shared help implementation; Perf's standalone help continues to use the client tooltip.

**Copy text** is available as soon as a saved loading report is shown. It opens a separate **Copy report** dialog with that report's complete text, including its name, measured boundary, total duration, phases and every stored chain link. Copying includes the full chain regardless of the selected tab or scroll position. The text is focused and selected, with a visible instruction to press Ctrl+C and then paste. Selecting text in the original details field is not required. The user must press native Ctrl+C to write to the OS clipboard; opening the dialog does not perform a direct clipboard write.

The original details field remains read-only and leaves keyboard text handling to the client. **Close** or Escape in the copy dialog dismisses that dialog; closing the loading window also closes its copy dialog. Reopening the cached dialog uses the currently selected report, including older reports, without requiring the main window. With no saved loading report, the window explains when one will become available and disables the report picker and **Copy text**.

The close controls and Escape in the loading window dismiss it. Theme supplies the window, controls and shared dialog preferences when present; the standalone path scales to fit the screen. Both windows retain Theme's existing OnShow group-raising handler. The login/reload window defaults to `FULLSCREEN_DIALOG`, including its preference binding; an explicit shared layer preference still takes precedence. The copy dialog is hidden before its first show so Theme raises its frame group on that first opening as well as later openings. Opening the report picker dismisses its help, and Perf tooltips stay hidden until the choice list closes. Opening this report does not start a collector or install a frame-update callback.

Existing Enter/Escape text actions and cursor-based controls are retained. The Chain and Details tabs use the existing native button path. Full Tab navigation and physical controller navigation remain unverified. No game launch or control is allowed by project AGENTS. Production-driven geometry fixtures omit actual client font rendering and Theme artwork.
